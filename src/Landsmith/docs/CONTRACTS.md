# Landsmith: Engine-Facing Contracts

Risk: **runtime-sensitive** (Harmony patches on placement, private terrain state, network ownership of terrain data, UI and input).

Baseline: Valheim **1.0.20** (network version 41, Steam build 25909357), Unity 6000.0.75f1, BepInEx 5.4.23.5 (Valheim BepInEx pack), HarmonyX 2.9.0, as recorded in `docs/evidence/baseline.json`. Re-checked on 2026-10-15 by comparison with the archived 1.0.17 code (`reference/archive/1.0.17-25730771/decompiled`): 1.0.20 moves the ZDO cheat flag to the new internal `CheatUtils` (`IsCheated`/`SetCheated`, an int revision instead of a bool), bumps the save and network versions and changes drop and upgrade randomness. Of the members used here only the body of `Player.PlacePiece` changed (cheat flag storage); the Landsmith prefix still returns `false` before that body runs, and the replayed feedback members are unchanged. Prefab values were re-inspected in the changed bundle and are identical. Verified on 2026-10-07 against 1.0.17 and `reference/decompiled/assembly_valheim` and `assembly_utils` (ILSpy `ilspycmd` 11.1.0.9782) and `reference/assemblies/BepInEx.xml` / `0Harmony.xml`, and reviewed a second time by an independent pass over the same sources. Prefab values: `docs/evidence/prefabs.json`.

Clean-room design. ValheimTerrainTools 0.6.4 (icecub333) was used only as a feature reference from its public description and configuration file; its code was not inspected or copied.

## Design Summary

A Landsmith piece only selects a tool. When the player places it, the piece is not instantiated; `TerrainWriter` computes the whole stroke on the one-metre vertex lattice (`Core/Shaper.cs`) and writes the result into the vanilla `TerrainComp` arrays of every affected 64 m heightmap, with **one** save, one network update and one mesh rebuild per heightmap and click. A dry run on the existing data comes first, so zones the stroke would not change, and strokes that are refused (nothing to change, protected, unaffordable), never create a terrain compiler or take ownership. Other players and the server receive ordinary vanilla terrain data (`ZDOVars.s_TCData`) and need nothing installed.

## Planning And Performance

While a tool is selected, the preview outline is rebuilt only when the brush moves to another vertex, a setting changes, or every 0.3 s; its cost depends on the outline length. The cost plan (a read-only dry run that also refreshes the protection check for the red outline) runs at most every 0.2 s: it allocates a height grid of the brush area (about 35 kB at default settings, up to about 170 kB for a 30 m rotated square with soft edges), samples it, computes the stroke and searches the zones around it for no-build locations. It never creates or claims a compiler. A click writes each affected heightmap once.

## Undo

Undo snapshots the five arrays of each changed compiler before the edit (about 110 kB per compiler) together with the `DataRevision` it started from. It restores them only if the compiler object still exists, still has the same ZDO and that ZDO's `DataRevision` is still the one Landsmith saved; otherwise it refuses and drops the entry. Because restoring saves again, the next older entry for the same zone is moved to the new revision when it directly preceded the undone edit (`UndoChain`), so several steps can be undone in a row. History is in memory only, per session, and limited by `UndoSteps`.

## Uninstalling

Edits are ordinary vanilla terrain data and remain. The tools disappear from the Hoe. No custom ZDO keys, RPCs or saved settings are added to worlds.
